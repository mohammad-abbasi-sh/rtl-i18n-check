# rtl-i18n-check — بررسی فایل‌های لوکال راست‌به‌چپ

[🇬🇧 English README](README.md)

**لایه‌ای که چکرهای i18n ندارند.** یک Agent Skill و چکر قطعی
برای فایل‌های لوکال فارسی/عربی/اردو/عبری که باگ‌های رندر راست‌به‌چپ
را می‌گیرد: نبود ایزولاسیون bidi، گم‌شدن نیم‌فاصله، قاطی‌شدن
حروف عربی و فارسی (ي/ک)، قاطی‌شدن رقم‌ها، فرم‌های جمع ناقص،
کاراکترهای کنترلی bidi، و پلیس‌هولدرهای ترجمه‌شده یا گم‌شده.

## مشکل چیست؟

ایجنت کل فایل لوکال را در یک مرحله ترجمه می‌کند، بیلد سبز می‌شود،
JSON معتبر است — و رشته‌های تحویلی برعکس رندر می‌شوند، عددها
جابه‌جا می‌شوند یا عربی ماشینی تحویل داده می‌شود. مارس ۲۰۲۶ یک
تیم همین‌طور یک باگ ۲٫۴ میلیون دلاری داد بیرون: «نسخه عربی اپ
داشت چرند رندر می‌شد. سلام‌ها برعکس. عددها سر جایشان نبودند.
CI سبز بود. استیجینگ خوب به نظر می‌رسید. تیم QA انگلیسی تایید
کرده بود.»

چکرهای عمومی i18n (مثل StringLane و Locale Guard) کلید گمشده و
پلیس‌هولدر را چک می‌کنند — ولی هیچ‌کدام bidi و نیم‌فاصله و
حروف و رقم را چک نمی‌کنند. این اسکیل همان لایه است؛ جایگزین
آن‌ها نیست، مکمل آن‌هاست.

## شروع سریع

```bash
# بررسی فایل لوکال فارسی (زبان از نام فایل تشخیص داده می‌شود)
python3 skills/rtl-i18n-check/scripts/rtl_i18n_check.py locales/fa.json

# مقایسه با لوکال مرجع — پلیس‌هولدرها باید برای هر کلید یکی باشند
python3 skills/rtl-i18n-check/scripts/rtl_i18n_check.py locales/fa.json --source locales/en.json

# اصلاح مکانیکی (فایل locales/fa.fixed.json را می‌سازد، ورودی دست نمی‌خورد)
python3 skills/rtl-i18n-check/scripts/rtl_i18n_check.py locales/fa.json --fix --source locales/en.json

# فایل اصلاح‌شده را دوباره چک کنید تا خروجی ۰ شود
python3 skills/rtl-i18n-check/scripts/rtl_i18n_check.py locales/fa.fixed.json --source locales/en.json
```

کد خروج: `0` = بدون خطا · `1` = خطا پیدا شد · `2` = خطای
استفاده یا فایل خواندنی/پارس‌شدنی نیست.

## چک‌ها

| چک | چه چیزی خطا می‌شود |
|---|---|
| RTL-01 ایزولاسیون bidi | جزیره LTR (نام لاتین، URL، ایمیل، `{placeholder}`، `$5`) وسط متن RTL بدون FSI…PDI یا `<bdi>` |
| RTL-02 نیم‌فاصله | در فارسی/اردو: `می شود` و `کتاب ها` با فاصله به‌جای نیم‌فاصله |
| RTL-03 حروف | ي/ك/ة عربی در فایل فارسی (یا ی/ک/گ/چ/پ/ژ فارسی در فایل عربی) |
| RTL-04 رقم‌ها | دو اسکریپت رقم در یک رشته؛ یا رشته‌ای با اسکریپت اقلیت فایل |
| RTL-05 جمع‌ها | فرم‌های CLDR ناقص (عربی شش فرم می‌خواهد، فارسی دو فرم)؛ فرم‌های zero/one/two عربی نباید پلیس‌هولدر عدد داشته باشند |
| RTL-06 کاراکترهای کنترلی | کاراکترهای override (مثل RLO) یا ایزولیت‌های بدون جفت |
| RTL-07 پلیس‌هولدرها | نام پلیس‌هولدر غیر ASCII؛ یا با `--source`، مجموعه پلیس‌هولدر متفاوت از لوکال مرجع |

فرمت‌ها: JSON (شامل i18next تودرتو)، ARB (فلاتر)،
`strings.xml` اندروید (شامل `<plurals>`)، PO (شامل فرم‌های جمع)،
YAML. عددهای خالص وسط متن RTL عمداً خطا نمی‌گیرند — طبق
الگوریتم bidi یونیکد درست رندر می‌شوند؛ فقط عددِ چسبیده به متن
لاتین یا علامت ارز مشکل دارد. دلیل هر قانون در
`skills/rtl-i18n-check/references/rtl-rules.md` آمده است.

## قرارداد

1. **اول چک کن، حدس نزن.** ابزار قطعی است — جدول کدپوینت و
   الگوریتم bidi، بدون مدل و بدون شبکه.
2. **اصلاح مکانیکی، بعد بازبینی.** `--fix` فقط اصلاح‌های
   مکانیکی امن (RTL-01 تا RTL-04) را در فایل `.fixed` جدید
   اعمال می‌کند. RTL-05/06/07 به انسان نیاز دارند.
3. **اصلاح را اثبات کن.** فایل اصلاح‌شده را دوباره چک کن تا
   خروجی ۰ شود؛ بعد گزارش بده اصلاح شده است.
4. **محدوده را بگو.** این اسکیل لایه *متن* RTL فایل‌های لوکال
   را چک می‌کند؛ نه کلید گمشده و انگلیسی ترجمه‌نشده را، نه
   چیدمان RTL (CSS و آیکون‌ها) را.

## تست‌ها

```bash
python3 -m unittest discover -s tests
```

۵۹ تست — تست واحد هر چک، تست لودر هر پنج فرمت، اجرای سرتاسری
روی فیکسچرها (فایل فارسی خراب: ۱۵ خطا و ۱ هشدار؛ فایل تمیز:
۰/۰؛ فایل عربی خراب: ۵ خطا)، رفت‌وبرگشت `--fix`، کدهای خروج
CLI، و ۴ تست سرتاسری سرور MCP — همه پاس می‌شوند، بدون شبکه.
